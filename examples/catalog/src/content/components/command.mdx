## Usage

```tsx
import {
  Command,
  CommandEmpty,
  CommandGroup,
  CommandInput,
  CommandItem,
  CommandList,
} from "@robomous/ui-core";

export function QuickActions() {
  return (
    <Command>
      <CommandInput placeholder="Search a command" aria-label="Search a command" />
      <CommandList>
        <CommandEmpty>Nothing matches.</CommandEmpty>
        <CommandGroup heading="Datasets">
          <CommandItem value="new dataset">New dataset</CommandItem>
        </CommandGroup>
      </CommandList>
    </Command>
  );
}
```

<Callout title="The value is what gets matched">
  `CommandItem`'s `value` drives the filter, not the text you render. Give it the words a reader
  might type, and add `keywords` for synonyms, such as a robot's site, that should match without
  being part of the value.
</Callout>

## Composition

```text
Command
├─ CommandInput
└─ CommandList
   ├─ CommandEmpty
   ├─ CommandGroup
   │  ├─ CommandItem
   │  │  └─ CommandShortcut
   │  └─ CommandItem
   └─ CommandSeparator

CommandDialog
└─ Command
   └─ … (as above)
```

## Examples

### Actions with icons and shortcuts

The everyday shape: a field at the top, a scrolling list beneath it, nothing hidden behind a trigger.
Lead each action with an icon, show its key with `CommandShortcut`, and mark an action the reader
cannot take yet with `disabled`; it stays visible but is skipped by the arrows.

### In a popover

Put a `Command` in a `Popover` for a searchable picker where a `Select` would be too long to scan.
`data-checked` on a `CommandItem` draws the tick, so the current choice is visible when the list
opens. Close the popover in `onSelect`.

<Preview demo="command/popover">
  <InPopover client:load />
</Preview>

### Command palette

`CommandDialog` wraps a `Command` in a modal, and the app opens it from a button or Cmd/Ctrl+K.
Its `title` and `description` are `sr-only`: nobody sees them, but they name the dialog for a
screen reader in place of a visible heading. Close it in each item's `onSelect` once the command
has run.

## Guidelines

<Guidelines
  do={[
    "Group commands under short headings, and put the most-used group first.",
    "Write `value` in the words people type, and use `keywords` for aliases.",
    "Always render a `CommandEmpty`, so a search with no results says so.",
    "Close the dialog or popover in `onSelect` once the command has run.",
  ]}
  dont={[
    "Don't use a command list for a short, fixed choice; use a `Select` or `RadioGroup`.",
    "Don't make the palette the only route to an action; it is a shortcut.",
    "Don't put form fields in the list; items run or choose, they don't edit.",
    "Don't hide `CommandInput`; the field is what the reader's focus lives in.",
  ]}
/>

## Accessibility

cmdk renders the field as a `combobox` and the list as a `listbox` of `option`s, and keeps focus in
the field while the highlighted option moves through `aria-activedescendant`. `CommandDialog` is a
Radix Dialog, so focus is trapped and restored on close.

  keys={[
