## Usage

```tsx
import {
  Combobox,
  ComboboxContent,
  ComboboxEmpty,
  ComboboxInput,
  ComboboxItem,
  ComboboxList,
} from "@robomous/ui-core";

const CLASSES = ["vehicle", "pedestrian", "cyclist", "traffic-sign", "traffic-light"];

export function ClassFilter() {
  return (
    <Combobox items={CLASSES}>
      <ComboboxInput placeholder="Filter by class" aria-label="Class" />
      <ComboboxContent>
        <ComboboxEmpty>No matching classes</ComboboxEmpty>
        <ComboboxList>
          {(item: string) => (
            <ComboboxItem key={item} value={item}>
              {item}
            </ComboboxItem>
          )}
        </ComboboxList>
      </ComboboxContent>
    </Combobox>
  );
}
```

<Callout title="The list is a function">
  Pass the data to `items` on `Combobox`, and give `ComboboxList` a function child, called once per
  item after filtering. There is no separate render prop, and `ComboboxEmpty` shows itself once that
  list has nothing left to call it with.
</Callout>

## Composition

```text
Combobox
├─ ComboboxInput
├─ ComboboxChips
│  ├─ ComboboxChip
│  └─ ComboboxChipsInput
└─ ComboboxContent
   └─ ComboboxList
      ├─ ComboboxGroup
      │  ├─ ComboboxLabel
      │  └─ ComboboxCollection
      │     └─ ComboboxItem
      ├─ ComboboxItem
      ├─ ComboboxSeparator
      └─ ComboboxEmpty
```

## Examples

### Filter as you type

The plain form: strings in, one string out. The reader types, the list narrows, and Enter or a click
fills the input. Use it for a list long enough that scanning is slower than typing.

### Clearable

`showClear` on `ComboboxInput` swaps the trigger chevron for a clear button once a value is picked,
so emptying the field does not need the keyboard. Use it where "none" is a valid answer.

<Preview demo="combobox/clearable">
  <Clearable client:load />
</Preview>

### Groups

For categorised data, make each item of `items` a group, `{ value, items }`, and render
`ComboboxGroup` with a `ComboboxLabel` and a `ComboboxCollection` for the group's own items. A group
whose items are all filtered out disappears with its label.

<Preview demo="combobox/grouped">
  <Grouped client:load />
</Preview>

### Multi-select

Setting `multiple` collects values into an array. There is no input left to anchor the popup to, so
a multi-select swaps `ComboboxInput` for `ComboboxChips`, and `useComboboxAnchor` gives
`ComboboxContent` an element to position against instead.

<Preview demo="combobox/multi-select">
  <MultiSelect client:load />
</Preview>

### Controlled

`value` and `onValueChange` hand the selection to your state. It is `null` when nothing is chosen,
so type the state as `string | null`. Here it filters the list beside the field, which is the usual
reason to control it.

## Guidelines

<Guidelines
  do={[
    "Use a combobox when the list is long enough that typing beats scrolling.",
    "Write a specific `ComboboxEmpty` message that names what was searched.",
    "Pass objects with `value` and `label` when an item carries more than a string.",
    "Give the input an `aria-label` or a `FieldLabel` pointing at its `id`.",
  ]}
  dont={[
    "Don't use a combobox for five options or fewer; a `Select` is simpler.",
    "Don't use it to run commands; that is a `Command`.",
    "Don't use `ComboboxInput` with `multiple`; use `ComboboxChips`.",
    "Don't let the reader type a value that is not in the list and expect it to stick.",
  ]}
/>

## Accessibility

The input is a `combobox` with `aria-expanded` and `aria-controls`, and the popup is a `listbox` of
`option`s. Focus stays in the input while the highlighted option is announced through
`aria-activedescendant`.
