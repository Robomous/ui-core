## Usage

```tsx
import {
  Sidebar,
  SidebarContent,
  SidebarGroup,
  SidebarGroupContent,
  SidebarGroupLabel,
  SidebarInset,
  SidebarMenu,
  SidebarMenuButton,
  SidebarMenuItem,
  SidebarProvider,
  SidebarTrigger,
} from "@robomous/ui-core";
import { DatabaseIcon } from "@robomous/ui-core/icons";

export function AppShell({ children }: { children: React.ReactNode }) {
  return (
    <SidebarProvider>
      <Sidebar>
        <SidebarContent>
          <SidebarGroup>
            <SidebarGroupLabel>Platform</SidebarGroupLabel>
            <SidebarGroupContent>
              <SidebarMenu>
                <SidebarMenuItem>
                  <SidebarMenuButton isActive>
                    <DatabaseIcon />
                    <span>Datasets</span>
                  </SidebarMenuButton>
                </SidebarMenuItem>
              </SidebarMenu>
            </SidebarGroupContent>
          </SidebarGroup>
        </SidebarContent>
      </Sidebar>
      <SidebarInset>
        <SidebarTrigger />
        {children}
      </SidebarInset>
    </SidebarProvider>
  );
}
```

<Callout title="The panel is fixed to the viewport">
  `collapsible="offcanvas"` and `"icon"` render the panel `position: fixed`, which is right for a
  real app shell. The demos on this page sit inside a card instead, so each wraps its shell in a
  box with `contain-layout` (a new containing block for the fixed panel) and gives `Sidebar`
  `className="h-full"`. In your app, leave both off.
</Callout>

<Callout title="It remembers where the reader left it">
  Uncontrolled and without `defaultOpen`, `SidebarProvider` restores the last state from the
  `sidebar_state` cookie before the first paint, and writes it on every toggle. A server that reads
  the cookie can pass `defaultOpen` itself so the first HTML already matches. `persist={false}`
  turns both off; the secondary demos on this page use it, along with `keyboardShortcut={false}`,
  so they don't share one state and one shortcut.
</Callout>

## Composition

```text
SidebarProvider
├─ Sidebar
│  ├─ SidebarHeader / SidebarFooter
│  ├─ SidebarInput
│  ├─ SidebarContent
│  │  └─ SidebarGroup
│  │     ├─ SidebarGroupLabel / SidebarGroupAction
│  │     └─ SidebarGroupContent
│  │        └─ SidebarMenu
│  │           └─ SidebarMenuItem
│  │              ├─ SidebarMenuButton
│  │              ├─ SidebarMenuAction / SidebarMenuBadge
│  │              ├─ SidebarMenuSkeleton
│  │              └─ SidebarMenuSub
│  │                 └─ SidebarMenuSubItem → SidebarMenuSubButton
│  ├─ SidebarSeparator
│  └─ SidebarRail
├─ SidebarTrigger
└─ SidebarInset
```

## Examples

### Groups, actions and sub-menus

The parts a full navigation tree uses: a search input in the header, a labelled group with its
own `SidebarGroupAction`, an active item wearing a `SidebarMenuBadge`, an item with a
hover-revealed `SidebarMenuAction` and a `SidebarMenuSub`, and a footer row. This one uses
`collapsible="none"`, a fixed panel that never moves, so it can sit in the flow of a document.

</Preview>

### Collapsing to icons

`collapsible="icon"` shrinks the panel to `--sidebar-width-icon` and keeps only the icons; the
default, `"offcanvas"`, hides it entirely. The `SidebarTrigger`, the `SidebarRail` along the edge
and `⌘/Ctrl+B` all call the same `toggleSidebar`. Pass `open` and `onOpenChange` to own the state,
and `tooltip` on each button to name it while collapsed; the provider already supplies the tooltip
context, so there is nothing to wrap.

<Preview demo="sidebar/collapsing">
  <Collapsing client:load />
</Preview>

### Inset

`variant="inset"` paints the sidebar's own surface behind the page and turns `SidebarInset` into
a rounded card on top of it, with a margin around it. Reach for it when the shell should feel like
a frame around the work instead of a column beside it.

<Preview demo="sidebar/inset">
  <Inset client:load />
</Preview>

### Floating

`variant="floating"` lifts the panel off the page's edge into its own ringed, shadowed box instead
of sharing a border with it. `side="right"` mirrors which edge it docks to, which suits an
inspector beside a canvas rather than primary navigation.

<Preview demo="sidebar/floating">
  <Floating client:load />
</Preview>

### Menu button sizes

Three heights for `SidebarMenuButton`: `sm` for dense secondary lists, `default` for navigation,
`lg` for a two-line row such as a workspace switcher or the signed-in user.

<Preview demo="sidebar/sizes">
  <Sizes client:load />
</Preview>

### Outline

`variant="outline"` rings a menu button with `--sidebar-border` instead of leaving it flat until
hover, for an item that should read as a control rather than a destination: a data source, a
switcher. The top group shows the flat default for comparison.

<Preview demo="sidebar/outline">
  <Outline client:load />
</Preview>

### Loading

`SidebarMenuSkeleton` stands in for a row before its label is known; `showIcon` reserves the space
the icon will take once it lands. Each skeleton picks its own width between 50% and 90%, so the
placeholder doesn't read as a table.

## Guidelines

<Guidelines
  do={[
    "Group related destinations under a `SidebarGroupLabel` and mark the current page with `isActive`.",
    "Use `collapsible=\"icon\"` for shells people live in, and give every button a `tooltip`.",
    "Wrap an icon-only action in `sr-only` text so its name is announced.",
    "Put the signed-in user and workspace switcher in `SidebarHeader` and `SidebarFooter`.",
  ]}
  dont={[
    "Don't nest more than one `SidebarMenuSub` level; deeper trees belong on a page.",
    "Don't let two sidebars on one page both answer ⌘/Ctrl+B; pass `keyboardShortcut={false}` to all but one.",
    "Don't use a sidebar for in-page tabs or a table of contents; it navigates the whole app.",
    "Don't put page content in the panel; it is for navigation and context only.",
  ]}
/>

## Accessibility

Navigation links belong in a list: `SidebarMenu` renders a `ul` and each `SidebarMenuItem` an `li`,
and `isActive` sets `data-active` for styling, so also pass `aria-current="page"` on the link that
is current. Below 768px the panel becomes a modal `Sheet`, with a visually hidden title, focus
trapping and Escape to close. `SidebarTrigger` carries an `sr-only` "Toggle Sidebar" label.
