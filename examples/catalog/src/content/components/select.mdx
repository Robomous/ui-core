## Usage

```tsx
import { Select, SelectContent, SelectItem, SelectTrigger, SelectValue } from "@robomous/ui-core";

export function ModelVersion() {
  return (
    <Select defaultValue="v3.2">
      <SelectTrigger aria-label="Model version">
        <SelectValue />
      </SelectTrigger>
      <SelectContent>
        <SelectItem value="v3.2">detector-v3.2 (production)</SelectItem>
        <SelectItem value="v3.1">detector-v3.1 (previous)</SelectItem>
      </SelectContent>
    </Select>
  );
}
```

<Callout title="Give the trigger a name">
  `SelectTrigger` shows the chosen value but not a label. Name it with `aria-label`, or put it in a
  `Field` and point a `FieldLabel` at it with `htmlFor` and the trigger's `id`.
</Callout>

## Composition

```text
Select
├─ SelectTrigger
│  └─ SelectValue
└─ SelectContent
   ├─ SelectScrollUpButton
   ├─ SelectGroup
   │  ├─ SelectLabel
   │  └─ SelectItem
   ├─ SelectSeparator
   └─ SelectScrollDownButton
```

## Examples

### Controlled

Use `value` and `onValueChange` when something else follows the choice. Here the hint under the
field updates with the format. Mark an option you cannot offer yet with `disabled` on its
`SelectItem`; it stays visible but cannot be chosen.

</Preview>

### Groups

`SelectGroup` and `SelectLabel` split a long list into named sections, with `SelectSeparator`
between them. Reach for groups once a list passes about seven items and has a natural category.

<Preview demo="select/groups">
  <Groups client:load />
</Preview>

### With icons

An icon placed inside a `SelectItem` is part of its text, so the closed trigger repeats it. Use
icons when the options differ in kind, such as sensors or file types, and skip them when they
would be the same on every row.

<Preview demo="select/with-icons">

</Preview>

### Sizes

Two trigger heights: `default` for a form, `sm` for a dense toolbar or table header. Both keep the
same radius scale as the rest of the field controls.

<Preview demo="select/sizes">
  <Sizes client:load />
</Preview>

### Multiline

The trigger is `whitespace-nowrap` by default, so a long value clips. `multiline` lets the closed
trigger wrap and grow to its value instead; the demo sets the two side by side. `line-clamp-none` on its own would leave the value on
one line, overflowing the box, so the prop does both jobs together.

<Preview demo="select/multiline">
  <Multiline client:load />
</Preview>

### Position

`SelectContent` defaults to `position="item-aligned"`, which lays the list over the trigger so the
selected option sits where the value was, as a native select does. `position="popper"` opens below
the trigger like a menu and matches its width. Use it in toolbars, where covering the trigger
would hide the context.

<Preview demo="select/position">
  <Position client:load />
</Preview>

### Disabled

Disabled keeps the arrow cursor and drops to half opacity: nothing will respond to a press. Say
nearby why the choice is locked.

## Guidelines

<Guidelines
  do={[
    "Use a select for four or more options, or when space is tight.",
    "Preselect the common choice with `defaultValue`, or give `SelectValue` a placeholder.",
    "Group long lists with `SelectGroup` and `SelectLabel`.",
    "Make the trigger full width inside a form so its edge lines up with the inputs around it.",
  ]}
  dont={[
    "Don't use a select for two or three options the reader should compare; use a `RadioGroup`.",
    "Don't hide an action in a select; commands belong in a `DropdownMenu`.",
    "Don't put long lists with search needs in a select; use a `Combobox`.",
    "Don't leave the trigger without a label or an `aria-label`.",
  ]}
/>

## Accessibility

Radix renders the trigger as a `button` with `role="combobox"` and `aria-expanded`, and the open list
as a `listbox` of `option`s, so a screen reader announces the value and the position in the list.
Inside a `<form>`, pass `name` and Radix adds a hidden native `<select>` so the value posts.
