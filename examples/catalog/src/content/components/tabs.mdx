## Usage

```tsx
import { Tabs, TabsContent, TabsList, TabsTrigger } from "@robomous/ui-core";

export function DatasetSections() {
  return (
    <Tabs defaultValue="schema">
      <TabsList aria-label="Dataset sections">
        <TabsTrigger value="schema">Schema</TabsTrigger>
        <TabsTrigger value="batches">Batches</TabsTrigger>
      </TabsList>
      <TabsContent value="schema">
        Six classes: person, forklift, pallet, box, cone, vehicle.
      </TabsContent>
      <TabsContent value="batches">148 batches, 1.2M frames in total.</TabsContent>
    </Tabs>
  );
}
```

<Callout title="Name the list, match the values">
  `TabsList` has no visible label, so give it an `aria-label` describing what it switches between.
  Each `TabsTrigger` is paired with its panel by `value`, so a trigger whose value has no matching
  `TabsContent` selects an empty region.
</Callout>

## Composition

```text
Tabs
├─ TabsList
│  └─ TabsTrigger
└─ TabsContent
```

## Examples

### Variants

`default` raises the active trigger on a muted track: it reads as a segmented control and suits
a short set in a card or a toolbar. `line` clears the track and underlines the active trigger,
which is the quieter choice for the main sections of a page.

</Preview>

### With icons

An icon with `data-icon="inline-start"` leads the label and the trigger trims its padding on that
side. Use it when the sections are kinds of view and a glyph speeds up scanning; keep the words,
since the icons alone are rarely enough.

<Preview demo="tabs/with-icons">
  <WithIcons client:load />
</Preview>

### Vertical

`orientation="vertical"` places `TabsList` beside its panels. The triggers fill the list's width
and left-align their labels, and the `line` underline moves to the trailing edge. It suits a settings
page with a few sections and a lot of room.

<Preview demo="tabs/vertical">
  <Vertical client:load />
</Preview>

### Controlled

Pass `value` and `onValueChange` when something outside the list has to move the selection, such as
a Continue button in a multi-step form. The tabs stay clickable, so a reader can still jump back.

<Preview demo="tabs/controlled">
  <Controlled client:load />
</Preview>

### Manual activation

By default a trigger activates the moment it receives focus, so arrowing across the row shows
every panel in turn. When a panel is costly to render or load, set `activationMode="manual"`: the
arrow keys then only move focus, and Enter or Space opens the panel.

<Preview demo="tabs/manual">
  <Manual client:load />
</Preview>

### Disabled

A `disabled` trigger stays in the row, dimmed and unselectable, so the set of sections doesn't
shift under the reader. Use it for a section that exists but is not available yet.

## Accessibility

Radix Tabs gives the list `role="tablist"`, each trigger `role="tab"` with `aria-selected`, and each
panel `role="tabpanel"` linked back to its trigger. The list is one tab stop with roving focus, and the
active panel is the next stop after it.
