## Usage

```tsx
import { Alert, AlertDescription, AlertTitle } from "@robomous/ui-core";
import { TriangleAlertIcon } from "@robomous/ui-core/icons";

export function IngestNotice() {
  return (
    <Alert variant="warning">
      <TriangleAlertIcon />
      <AlertTitle>Ingest paused</AlertTitle>
      <AlertDescription>The bucket is unreachable. Retrying in a minute.</AlertDescription>
    </Alert>
  );
}
```

<Callout title="The variant also picks how it is announced">
  `default`, `warning` and `destructive` render `role="alert"` and are read out the moment they
  mount; `info` and `success` render `role="status"` and wait for a pause. Pick the variant for
  what the notice means, not for how it looks.
</Callout>

## Composition

```text
Alert
├─ <Icon />            optional, takes the first column
├─ AlertTitle
├─ AlertDescription
└─ AlertAction         optional, its own column on the right
```

## Examples

### Variants

Every variant is the same quiet box: no fill, a neutral hairline, the title in the foreground and
the description muted. The variant colours the icon and nothing else, since that is the one mark
that has to be read at a glance; the title says the rest in words. `default` keeps a muted icon.

### With an action

`AlertAction` takes a column of its own on the right, so the title and description wrap before it
instead of running underneath. Its box is one title line tall, which lines a small button or an
icon button up with the first line of text. Use it for the one thing that resolves the notice.

</Preview>

### Dismissible

An `Alert` does not manage its own visibility. For a notice the reader can put away, hold the state
yourself and put a ghost icon button in `AlertAction`. Reserve this for information; a warning that
still applies should stay on the page.

</Preview>

### Parts are optional

A title alone is enough for a one-line fact, and a description alone reads as a plain note. Without
an icon the content simply takes the full width.

### Longer descriptions

The description takes paragraphs and links. Paragraphs get spacing between them and links are
underlined, so a notice can point to the next step without extra markup.

## Guidelines

<Guidelines
  do={[
    "Lead with a title that states the condition, and use the description for cause and next step.",
    "Match the variant to the severity: `warning` for what needs attention, `destructive` for what failed.",
    "Put the one resolving action in `AlertAction` instead of burying it in the description.",
    "Place an alert next to the content it concerns, not at the top of an unrelated page.",
  ]}
  dont={[
    "Don't use an alert for a result of something the reader just did; that is a toast.",
    "Don't stack several alerts on one view; merge them or keep the most severe.",
    "Don't rely on colour alone. The title must say what is wrong.",
    "Don't use `destructive` for a field-level problem; use an inline `ErrorMessage`.",
  ]}
/>

## Accessibility

The root is a plain `div` with a role chosen from the variant: `alert` for `default`, `warning` and
`destructive`, `status` for `info` and `success`. There is no live-region prop and nothing to wire
up. Keep an icon decorative; the title already carries the meaning. An `AlertAction` button is a
normal button in the tab order, so an icon-only one needs an `aria-label`.
